Overview

This project documents a Docker-based workflow for processing a local copy of a website. A Python script runs inside a Docker container to discover HTML files and remove selected page elements identified by the IDs header, sidebar and footer.

The workflow covers preparing the project environment, building a Docker image, running the processing script, reviewing the reported results, accessing the output directory and stopping Docker Desktop on macOS.

Project objective

Produce a separate collection of processed HTML files while keeping the original website copy in its own input directory.

Commands and Explanations

1. Check Docker

docker --version

Checks whether Docker is installed and available in the terminal.

Observed result: Docker version 29.8.0, build 88096ef.

2. Create the project directory

mkdir html-editor
cd html-editor
  • mkdir creates the project workspace.
  • cd changes the current directory to that workspace.

3. Create or edit the Dockerfile

nano Dockerfile

Opens the Nano editor to create or edit the Dockerfile. This file defines the instructions used to build the Docker image.

The exact Dockerfile contents were not included in the supplied terminal transcript.

4. Build the Docker image

docker build -t html-editor .
  • docker build starts the image build.
  • -t html-editor assigns the image a name.
  • . uses the current directory as the build context.

Observed result: The image build completed successfully. The build output showed the python:3.12-slim base image and installation of beautifulsoup4.

5. Create or edit the Python script

nano edit_html.py

Opens the Python processing script in Nano. The script performs HTML-file discovery and cleanup.

The exact source code was not included in the transcript.

6. Inspect the project directory

ls

Lists files and folders in the current directory.

Observed entries: Dockerfile, edit_html.py and websitename-copy.

7. Run the file-discovery pass

docker run --rm -v "$(pwd):/app" html-editor python edit_html.py

Runs the Python script inside a temporary container.

  • docker run starts a container.
  • --rm removes the container after it exits.
  • -v "$(pwd):/app" mounts the current host directory at /app inside the container.
  • html-editor identifies the image.
  • python edit_html.py executes the script.

Observed result: The first recorded run reported finding 354 HTML files and printed their paths.

cd ~/html-editor
nano edit_html.py

Returns to the project directory under the user's home directory and reopens the Python script for editing.

Accessing the Output

The script reported the output directory as /app/websitename-cleaned. However, the /app path is inside the Docker container. It is not the direct path used by the macOS host shell.

Incorrect host-side command

cd /app/websitename-cleaned

This command failed in the host shell because /app is the container mount point.

Correct host-side commands

cd ~/html-editor/websitename-cleaned
ls

Assuming the project is located in ~/html-editor, these commands navigate to the output directory and list its contents.

Stopping Docker Desktop on macOS

After the cleanup and verification are complete, Docker Desktop can be stopped.

Option 1: Using Terminal

osascript -e 'quit app "Docker"'

Asks macOS to quit the Docker Desktop application.

Option 2: Using the Docker Desktop menu

  1. Click the Docker whale icon in the macOS menu bar.
  2. Select Quit Docker Desktop.

Verify that Docker has stopped

docker info >/dev/null 2>&1 && echo "Docker is running" || echo "Docker is not running"

Expected output after Docker Desktop has fully stopped:

Docker is not running

This command suppresses normal output and error messages from docker info. It checks whether the Docker CLI can communicate with the Docker daemon. If Docker Desktop is still shutting down, wait briefly and run the check again.

Important Docker notes
  • Quitting Docker Desktop stops the Docker daemon and its running containers.
  • The --rm option removes the temporary container after it exits. It does not remove the html-editor image.
  • The cleaned HTML files are stored in the mounted host project directory. Quitting Docker Desktop does not delete those files.
  • Start Docker Desktop again and wait for its engine to become available before running more Docker commands.

Conclusion

A Docker-based Python environment was successfully prepared and used to process a local collection of website HTML pages. The processing script found 354 HTML files and reported removing header, sidebar and footer elements 353 times each.

The cleaned output was directed to websitename-cleaned. The command-line issue occurred afterward, when a container-internal path was used from the host macOS shell. This path issue does not indicate that the cleanup operation itself failed.
